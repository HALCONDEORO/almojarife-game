# String IDs and locale files (M0, issue #7)

Decision:
- Every visible text is a string ID. No text is hard-coded in code.
- Files: `locales/es.json` (source) and `locales/en.json`. Flat JSON: `{ "ui.menu.new_game": "Nueva partida" }`.
- ID format: `area.screen.item`, lowercase, dots and underscores only.
- Placeholders: `{name}` style. Plurals: separate IDs with `_one` and `_other` suffixes.
- Numbers, dates and currency are formatted in code by locale, never inside strings.
- A test fails the build if an ID exists in `es.json` but not in `en.json`, or the placeholders differ.
- Fallback: missing EN string falls back to ES and logs a warning in dev.
- Mission texts live in `locales` too, keyed `mission.<id>.title`, `.goal`, `.fail`.

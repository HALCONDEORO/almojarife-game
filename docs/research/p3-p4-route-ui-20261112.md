# P3/P4: route planning and market visibility

12 November 2026. Clean-room public-document study, Web UI scope.

The useful lesson is control over an understandable plan, not more automatic trading rules. Almojarife already has multi-stop routes, price limits, a cash reserve and a route diary. Its editor lacks a direct way to move a whole stop. The first proposal is explicit up/down controls that keep the city's complete instructions together. This changes the draft only, not the running route or economy.

## Findings and proposals

| Priority | Public finding, paraphrased | Current source check | Concrete proposal |
|---|---|---|---|
| 1 | P4's manual describes ordered cities followed by product rules. A community guide reports accidental changes when dragging cities. [1,2] | `web/main.mjs` route editor adds/deletes rows but has no reorder action. | Add keyboard-accessible Up/Down controls. Move the whole row object, retain price strings, restore focus to the moved row, disable boundary actions. Keep existing explicit activation. |
| 2 | P3 community documentation describes independent buy ceilings and sell floors; its published guide also discusses goods priority. [3,4] | `src/game/routes.mjs` already uses maxPrice/minPrice and ordered rules. Current UI accepts one buy and one sell product per stop. | Label buy/sell limits with words as well as symbols. Explain that moving a stop does not change its rules. Do not add a second economic algorithm. |
| 3 | P4's manual ties its market status indicator to stock/need and shows average acquisition/production cost separately. It says changing trade quantity changes the price. [1] | Almojarife Market already shows stock, average cargo cost, transaction previews and quantity controls; `marketdesk.mjs` preserves information age for other ports. | Audit labels and accessible descriptions before adding indicators. Keep stale destination information marked stale. Do not infer exact profit from an old quote. |
| 4 | A contemporary P4 review describes configurable automatic routes as a way to reduce repetitive manual trading. [5] | Almojarife already has automatic circuits and reasons in its route diary. | Improve the existing route editor and explain skipped trades, rather than adding a separate 'smart captain' system in Web UI. |

## Evidence and uncertainty

1. Publisher manual, Patrician IV, public PDF, sections "The Trade Window" and "Creating a Trade Route": https://download.kalypsomedia.com/manuals/p4_manual-en.pdf . Read relevant sections. High confidence for the documented design, not a measured runtime guarantee.
2. Steam Community, Heraclitus, "Patrician IV Guide", identifies Rise of a Dynasty: https://steamcommunity.com/sharedfiles/filedetails/?id=682751098 . Read trade screen and auto-route sections. Community observations, including drag sensitivity, are anecdotal and version-specific. Do not treat its claimed edge cases as universal engine facts.
3. Patrician III community wiki, "Trade Routes": https://patrician3.fandom.com/wiki/Trade_Routes . Read. Community source, medium confidence. Its town-count claim differs from the manual search excerpt, so no town limit is adopted or asserted here.

Read price-limit, quantity and priority sections. Independent guide, medium confidence. Its displayed date differs from search metadata; use the page date.
5. Gaming Nexus, Tom Bitterman, review dated 15 November 2010: https://www.gamingnexus.com/article/patrician-iv/item2819.aspx . Read automation discussion. Contemporary independent review, useful corroboration, not a specification.
6. Patrician III manual publicly hosted by Steam: http://cdn.akamai.steamstatic.com/steam/apps/33570/manuals/manual-patrician3.pdf . The fetched extract contains the contents headings for chapter 8.4 but not the full relevant chapter. Search highlights show the chapter, but they are insufficient to settle version-dependent limits. ## Implementation boundary and acceptance

Reference source: `c4b7e8e48469974c9b00c78fddb42742db7b0489`, inspected 12 November 2026. Roadmap/backlog contain historical "next" items already implemented; code takes precedence.

First patch is presentation-only: route-draft ordering, ES/EN accessible labels, draft integrity tests and real desktop Chrome checks. No auto-activation, new rules, balancing, save-format changes or remote market-information disclosures. Reordered drafts can still be invalid under existing adjacent-stop rules; the existing activation validator remains authoritative.

No binaries were opened, disassembled or extracted. No competitor code, assets, tables, city lists, numeric balance values or text are included. These are original summaries of public descriptions. No formula has been experimentally recovered; none is claimed.

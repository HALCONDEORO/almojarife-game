# Governance

## Who decides
The project owner (@HALCONDEORO) is the maintainer and has the final say on design and on what is merged. Trusted contributors can be given review rights later, by the owner.

## How a change gets in
- Every change goes through a pull request. Nobody pushes to `main`; it is protected.
- Required: the CI checks pass (tests and code scanning) and at least one maintainer review. An automated review (CodeRabbit) is an extra opinion, not a gate.
- Design changes (new mechanics, screens, balance) start as an issue. Content additions (a port, a good, a translation) can go straight to a pull request.
- Merges are squash merges with a clear title.

## Scope and quality
The aim is a game with the depth of a classic Hanse trading game, built step by step (see [docs/ROADMAP.md](docs/ROADMAP.md)). Dates are a plan: scope is cut before dates move.

## Licences and credits
Code and data MIT, art and documents CC BY 4.0. Third-party material must be public domain, CC0, CC BY or MIT, and every file is listed in [CREDITS.md](CREDITS.md). Commits are signed off (DCO).

## No monetisation
No ads, tracking, accounts, purchases or paid features. This is a project made for fun and shared with anyone who wants it.

## Conduct
See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). The maintainer enforces it.
